# channels/

Every directory in here that contains a `.env` is **one 24/7 YouTube stream**,
with its own playlist, image set, visualisation, colour profiles and schedule.
Channels run independently — starting, stopping or restarting one does not
touch the others.

## Adding a stream

```bash
mkdir -p channels/lofi/{audio,images}
cp channels/example/.env.example channels/lofi/.env
chmod 600 channels/lofi/.env
```

Then edit `channels/lofi/.env` and paste that stream's YouTube key into
`YOUTUBE_STREAM_KEY`. Each stream needs its **own** key — create one per
YouTube channel in Studio (Go Live → Stream → Select stream key → reusable).

Drop audio into `channels/lofi/audio/` and images into `channels/lofi/images/`.
Both are read live: adding or removing files does not restart anything.

Repeat for each stream you want. Supported range is 1–8.

## Layout

```
channels/
├── example/              <- template, not a running stream (no .env)
│   └── .env.example
├── lofi/                 <- a stream
│   ├── .env              <- stream key + per-stream overrides   (gitignored)
│   ├── config.yaml       <- playlist order, visualisation, schedule (gitignored)
│   ├── audio/            <- music for this stream                (gitignored)
│   ├── images/           <- slideshow images                     (gitignored)
│   ├── profiles/         <- generated colour profiles, one JSON per image
│   └── docker-compose.yml <- generated by the backend; do not hand-edit
└── nature/               <- another stream, entirely independent
    └── ...
```

`example/` is deliberately not a stream — it has no `.env`, so nothing starts
from it. Copy it, don't run it.

## What lives where

| Setting | File |
|---|---|
| YouTube stream key | `channels/<name>/.env` |
| Resolution, fps, encoder, CPU/memory limits | `channels/<name>/.env` |
| Icecast mount names | `channels/<name>/.env` |
| Playlist order, image order, visualisation, presets, schedule | `channels/<name>/config.yaml` |
| Ports, host paths, Icecast credentials, backend auth | the root `.env` |

The split is deliberate: `.env` holds secrets and things Docker needs at
container-creation time, `config.yaml` holds everything the backend can change
on a running stream without restarting it.

## Capacity

Measured on a 7-core host: roughly **1.1 cores per 720p stream** with three
visualisation plugins loaded. Reserve about a core for the OS and the shared
services, then divide. See `docs/scaling.md`.

## Never commit

`.env`, `config.yaml`, `audio/`, `images/` and `profiles/` are all gitignored.
A stream key grants publish rights to your YouTube channel — treat
`channels/*/.env` like a password file (`chmod 600`).
